Project overview

A desk display for the numbers you actually watch.

CYD Monitor is a personal hardware and web project. The firmware runs on a single ESP32-3248S035 board; this site presents the build and recreates the interface in the browser.

01 / Brief

Glanceable, not another window.

PC temperatures and loads usually live behind a desktop app. CYD Monitor puts the essentials on a dedicated 3.5-inch panel that stays on the desk.

02 / Approach

Direct LAN polling.

The ESP32 joins the local Wi-Fi, reads LibreHardwareMonitor's JSON endpoint, scans the hardware tree and draws the result with TFT_eSPI. Six saved profiles map each network to its own endpoint.

03 / Result

One board, four screens.

Monitor, Clock, Animation and Settings share a 480 × 320 touch UI. The browser demo mirrors those screens with generated data so the project can be explored without the hardware.

Four screens, one glance

Built for a desk, not a debug console.

The firmware draws every screen with TFT_eSPI primitives at 480 × 320. Navigation is touch-first: header tabs, tappable cards, saved-network management, a paged theme gallery and a BOOT-key page shortcut. The browser demo recreates those controls; it does not control the board.

Hardware monitor

Walks the LibreHardwareMonitor tree and scores sensor candidates by type and label. Shows CPU and GPU temperature, load, package power or fan RPM when available, GPU hotspot and VRAM, plus RAM. Trend badges, 40-sample sparklines and a stale-data state.

AMD / Intel / NVIDIA · label-based discovery

Wi-Fi diagnostics

Signal percentage, RSSI, channel and SSID; local IP, gateway, subnet, MAC and DNS. Latency probes hit the gateway and one of three targets: Google, Cloudflare or Telkom. Six saved profiles each keep their own password and JSON URL.

Up to 6 profiles · NVS

Standby clock

NTP time from pool.ntp.org at GMT+7, with a full date line and a seconds meter. There is no RTC; the clock relies on Wi-Fi and the NTP sync.

pool.ntp.org · GMT+7

Pomodoro hub

10, 15, 25 and 45-minute presets, 1–60 minute manual adjustment, start/pause/resume/reset, a 24-block progress wave and a five-dot session display. The backlight blinks for eight seconds when a session ends.

PWM backlight alarm

Three animations

Matrix rain with 24 columns and 80–160 px/s fall speeds, a 50-star 3D starfield and a bouncing DVD sprite. Motion is time-based, and the on-screen HUD reports measured FPS.

24-column Matrix · FPS HUD

Eighteen themes

The firmware ships 18 RGB565 palettes, from DUO-TONE and E-INK to Neon Matrix, Aurora and Copper. Settings pages through them six at a time, and the selection is written to NVS.

3-page gallery · saved to NVS

From data.json to pixels

A local telemetry pipeline with a small footprint.

LibreHardwareMonitor exposes a JSON tree on the PC. The ESP32 walks that tree, classifies each hardware branch as CPU, GPU or RAM, and picks the strongest sensor by type and label. Wi-Fi credentials and the JSON URL are saved per network, so switching machines is a single tap.

  1. 01

    Flash the board

    PlatformIO builds src/main.cpp for esp32dev with the huge_app.csv partition. platformio.ini defines the ST7796 panel, SPI bus, touch CS and backlight pin.

  2. 02

    Serve the sensor tree

    Enable Options → Remote Web Server → Run in LibreHardwareMonitor. The examples in this project use port 8085 for the JSON endpoint.

  3. 03

    Join the setup AP

    On first boot, connect to CYD-MONITOR-AP and open 192.168.4.1. Pick the network and paste its JSON URL; the profile is saved in NVS.

  4. 04

    Share the interface

    Run this static site locally or with Docker. The browser build uses generated telemetry and does not connect to the board.

void httpFetchTask(void *pv) {
  JsonDocument filter;
  buildLhmFilter(filter.to<JsonObject>(), 7);

  for (;;) {
    if (!networkBusy && currentPage == 0 &&
        monitorSubPage == 0 &&
        WiFi.status() == WL_CONNECTED) {
      HTTPClient http;
      String url = getServerUrl();
      if (http.begin(url)) {
        http.setConnectTimeout(4000);
        http.setTimeout(10000);

        if (http.GET() == HTTP_CODE_OK) {
          JsonDocument doc;
          deserializeJson(doc, http.getStream(),
            DeserializationOption::Filter(filter),
            DeserializationOption::NestingLimit(12));

          ScanResult scan;
          scanSensorNode(doc.as<JsonVariant>(),
            HW_OTHER, -1, scan);
          finalizeScan(scan);
          commitLiveData(scan.data);
        }
        http.end();
      }
    }
    vTaskDelay(pdMS_TO_TICKS(400));
  }
}

Engineering notes

Small screen, small heap, no cloud.

A few constraints shaped the firmware and the demo.

Heap

Filter before parsing.

LibreHardwareMonitor's full tree is roughly 120 KB. The fetch task applies a JSON filter and a nesting limit so the ESP32 only keeps the fields the scanner uses.

Network

Local by design.

Telemetry goes directly from the PC to the board over the LAN. Wi-Fi profiles, endpoints and the theme choice live in NVS; there is no account or cloud service.

Scope

The demo is not a remote.

The browser build is a static simulation with generated telemetry. It does not talk to the ESP32 or to LibreHardwareMonitor.

Hardware & stack

One board, local data.

The ESP32-3248S035 "CYD" bundles an ESP32, a 3.5-inch 480 × 320 ST7796 panel, a touch panel and an LDR on one PCB. There is no cloud service in the telemetry loop.
